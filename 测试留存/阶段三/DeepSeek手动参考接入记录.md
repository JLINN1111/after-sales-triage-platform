# DeepSeek 手动参考接入记录

日期：2026年11月21日
范围：仅完成本地接入、隔离与自动化验证；未调用任何真实外部服务。

## 接入结论

DeepSeek 已作为“手动客服参考”能力接入，但默认关闭。常规工单提交、规则分诊、传统分类器和知识库检索均不会自动调用外部模型。

启用时必须同时在未纳入版本控制的本机 `.env` 中明确设置 `LLM_ENABLED=true` 与 `LLM_ALLOW_EXTERNAL_CALLS=true`，并配置 `LLM_PROVIDER=deepseek` 和 `DEEPSEEK_API_KEY`。密钥不写入代码、数据库、测试留存或版本库；已有系统环境变量优先于 `.env`。

## 功能边界

- 仅通过 `POST /tickets/<ticket_id>/llm-reference` 由客服显式发起。
- 仅请求客户摘要和下一步补充问题；要求返回 JSON。
- 返回内容不得改变类别、优先级、工单状态、规则结果或知识库命中，也不写回数据库。
- 仅当安全风险与停机均明确为“否”、必填信息完整且规则结果未要求人工确认时才可能调用。
- 安全风险或停机为“是/未知”、信息缺失、规则与模型冲突、模型调用失败或输出不合格时，一律阻断并转人工确认。

## 真实连通性验证

经项目负责人明确授权，已使用最小化非敏感样例完成一次真实调用验证。样例只包含“冷却风扇异常、设备仍运行、无停机、无安全风险”的通用描述，不含客户信息、设备编号、联系人、现场地址、报警代码或真实工单内容。

首次调用证明网络与密钥可用，但因提示未明确输出字段而被安全网关拒绝；随后补充“仅三个字段、类别必须与规则一致、禁止 Markdown 代码块和额外字段”的严格结构约束。本地新增结构约束测试通过后复测，返回状态为 `REFERENCE`，即输出通过结构校验且类别与规则一致。

此结果仅证明 DeepSeek 的最小化连通和安全网关链路可用，不构成真实业务准确率、稳定性或安全性验收。后续仍只可作为人工参考，不能投入自动分诊或自动处置。

## 工单详情页手动入口

在项目负责人授权真实工单文本按需发送后，工单详情页已在“分诊建议”之后、“客服处理”之前加入“DeepSeek 客服参考”区块。

- 仅当安全风险为否、未停机、规则未要求人工确认、无待补关键信息，且本机 DeepSeek 已显式启用时，才显示“生成客服摘要与补问建议”按钮。
- 点击按钮才发送故障现象描述和规则类别；不会自动调用，也不发送设备编号、联系人、地址等页面字段。
- 返回内容只在当前页面展示为“客服摘要”和“建议补问”，不写回数据库，不改变类别、优先级、工单状态或知识库。
- 不满足条件时展示阻断原因；调用或输出失败时只提示按人工流程处理，不暴露上游错误。

页面与安全回归验证：`测试用例.test_ticket_actions`、`测试用例.test_llm_guard`、`测试用例.test_llm_provider` 共 31 项通过；其中覆盖未启用提示、合格工单显示按钮、安全风险工单隐藏按钮，以及现有动作流转不受影响。
