# 故障词表字段说明（v0.1）

对应文件：`data/fault_taxonomy.json`
更新日期：2026-11-18
依据：《制造设备售后报修智能分诊平台 首版实施操作手册》模块 1

## 字段含义

| 字段 | 含义 | 取值 / 填写规则 |
|------|------|----------------|
| id | 故障类别编号 | 整数，1–6，稳定不变 |
| name | 故障类别名称 | 电气 / 机械 / 控制 / 液压气动 / 通讯 / 耗材 |
| device_types | 适用设备类型 | 该故障通常出现的设备范围 |
| symptoms | 可观察现象 | 客户能描述出来的外在表现，不写零件结论 |
| keywords | 判定关键词 | 命中即作为分类依据；与 `fault_categories.py` 保持一致 |
| counterexamples | 反例 | 看起来像但不属于本类的描述，并注明应归哪类 |
| priority | 优先级（基础） | 高 / 中 / 低 |
| priority_note | 优先级升级规则 | 说明基础级别在什么条件下升级 |
| transfer_to | 转派方向 | 该故障应转给的维修组或岗位 |
| human_review | 人工复核条件 | 何种情况必须转人工、不自动定论 |
| source | 来源 | **待确认**：需补厂家官方手册或题目给定资料的文件名/网址 |

## 说明

1. 反例的作用是防止误判：手册明确要求"先写可观察现象，再写关键词与反例；例如'无法启动'不能直接等同于某个具体零件故障"。
2. priority 填的是**基础**优先级，实际紧急度由 `core_algorithms.py` 的 `assess_urgency()` 结合高危信号词和是否停机再升级。
3. human_review 对应分诊的"低置信 / 高风险转人工"分支，是系统不做自动定论的边界。
4. source 目前统一为"待确认"，符合手册"不确定的内容填待确认、不要猜"的要求。等拿到厂家手册或题目资料后，逐条补录来源并升版本号。
