# 角色权限说明

## 适用范围

本平台是制造设备售后报修的分诊辅助工具。角色权限用于限制数据和流程操作，不得修改规则分诊、安全限制或现场维修结论。

## 角色划分

| 角色 | 可执行操作 | 不可执行操作 |
| --- | --- | --- |
| 报修业务人员 AGENT | 提交报修、上传或补充本人报修的附件、补充本人收到的待补充信息、查看自己提交的工单进度 | 查看他人报修、补问、转现场、确认、修订、关闭、删除工单；管理账户 |
| 售后处理人员 REVIEWER | 查看工单、查看或补充附件、补问、转现场处理、确认、修订、关闭、记录处理结果 | 删除工单；管理账户 |
| 平台管理员 ADMIN | 管理账户、角色启停、密码重置和公开知识资料 | 查看或处理工单、提交报修、使用报修信息对话助手；不能绕过安全风险、停机、未知状态、信息不完整和规则冲突时的人工确认要求 |

## 对话式信息采集助手

报修业务人员可在提交报修时，或在本人“待补充信息”工单中使用对话助手补充可观察信息。助手的字段建议必须由用户采用后才会填入表单；它不读取或复述分诊结论，不直接写入工单，也不能确认、转现场或关闭工单。

对话调用只发送必要的脱敏文本，不发送账户、设备编号、附件原文件或地址。大模型服务未启用、超时或返回格式不合格时，用户继续使用原有表单，不影响工单主流程。

## 强制业务边界

角色权限只控制“谁可以发起操作”。安全风险、停机、运行或安全状态未知、信息不完整、规则冲突的工单，仍由现有规则保守进入售后处理。售后处理人员和管理员也不能通过角色权限让系统给出自动现场维修结论。

## 首次初始化

在本机 `.env` 中填写 `BOOTSTRAP_ADMIN_USERNAME` 与 `BOOTSTRAP_ADMIN_PASSWORD`，保持 `AUTH_ENABLED=true`，然后运行：

```powershell
.venv\Scripts\python.exe 运行脚本\init_db.py
```

该脚本只在账户表为空时创建首个管理员，并且只保存密码哈希。账号创建后访问平台会进入登录页。真实密码、数据库文件和 `.env` 不得提交到 Git。

## 当前限制

当前版本已提供登录、会话、服务端权限校验、可信操作人留痕、报修人员仅查看本人工单，以及管理员网页创建账号、修改角色、启停账号和重置密码。尚未提供多人并发会话治理、密码重置后的全端会话失效、企业单点登录或网关级访问控制；这些能力应在面向真实企业部署前补齐。
