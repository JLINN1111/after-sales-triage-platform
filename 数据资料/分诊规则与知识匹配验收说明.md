# 分诊规则与知识匹配验收说明（V1）

## 1. 适用范围

本说明定义首版规则分诊和知识检索的输入、输出、优先级及验收案例。它只输出分诊建议和可追溯知识依据，不输出维修结论；任一安全风险、信息不足或知识不精确匹配情形均须建议人工确认。

## 2. 服务输入与输出

输入为一张已通过表单校验的工单，至少使用：`equipment_type`、`description`、`operating_state`、`shutdown`、`safety_risk`、`alarm_code_status`、`alarm_code`；`equipment_model` 为可选信息，缺失时只允许第一层参考匹配或人工补问。

输出必须包含以下字段：

```text
predicted_category, priority, evidence_codes, missing_fields,
follow_up_questions, knowledge_ids, reference_knowledge_ids,
knowledge_match_level, recommend_human,
handoff_reasons, model_version, triaged_at
```

`model_version` 固定为 `rules-v0.1`，用于标识当前规则版本。

## 3. 规则顺序

1. 先计算缺失字段并检查安全风险与停机状态。
2. 再从故障描述中提取可观察现象，判定粗粒度类别。
3. 最后检索知识库：先召回设备大类与子系统一致的参考候选，再执行精确设备确认。

`knowledge_match_level` 只能为 `EXACT`、`REFERENCE` 或 `NONE`：`EXACT` 可展示原厂具体处置方向；`REFERENCE` 只能展示参考候选和补问；`NONE` 不展示知识内容。`knowledge_ids` 只存精确命中，`reference_knowledge_ids` 只存第一层参考候选。

安全与人工规则优先于类别和知识检索：

| 条件 | 优先级 | 是否转人工 | 必须记录的原因 |
|---|---|---|---|
| `safety_risk=YES` 或 `shutdown=YES` | `URGENT` | 是 | 安全风险或设备停机 |
| `safety_risk=UNKNOWN` 或 `shutdown=UNKNOWN` | `HIGH` | 是 | 关键安全状态未确认 |
| 信息不足或类别冲突 | 不低于 `HIGH` | 是 | 信息不足或类别不明 |
| 无适用知识，但安全状态明确、未停机且类别线索充分 | 按安全与停机规则计算，可为 `NORMAL` | 是 | 无适用知识 |
| 上述情形均不存在 | `NORMAL` | 视知识匹配结果决定 | - |

## 4. 类别边界

| 类别 | 可采纳的直接线索 | 不足以单独判定的线索 |
|---|---|---|
| `ELECTRICAL_CONTROL` | 控制面板、控制器、供电、控制指令执行异常 | 仅“无法启动” |
| `MECHANICAL` | 传动部位异响、振动、卡滞、部件松脱 | 仅“停机” |
| `THERMAL_COOLING` | 温度超限、过热、冷却风扇或冷却能力异常 | 仅温度读数异常 |
| `SENSOR_COMMUNICATION` | 传感器读数异常、采集信号丢失、设备通信中断 | 未明确根因的报警 |
| `OTHER_UNKNOWN` | 无规则匹配、证据冲突、信息不足 | 不适用 |

若同时有多个同等强度类别线索，输出 `OTHER_UNKNOWN`，保留全部现象标签并转人工。

## 5. 知识匹配门槛

- 第一层参考匹配：设备大类和子系统一致时，可返回参考候选的 `knowledge_id`，但必须标注“参考候选”，同时转人工；不得展示为该设备的确定报警含义或维修结论。
- 第二层精确匹配：标准化后的 `brand`、`equipment_model`、`controller_system` 一致，软件版本符合范围，且报警码一致；或条目明确未限定报警码、同时设备键与核心现象一致。满足该条件时可返回对应的 `knowledge_id` 及其原厂处置方向。
- 未精确匹配：品牌或控制系统不同、型号不明、报警码不一致，均不得输出具体处置方向；应记录“未精确匹配”，保留第一层参考候选并转人工。
- 来源不完整、适用机型不明或未纳入正式知识库的资料不得参与匹配。当前正式知识库有 14 条公开原厂来源知识；公开基准设备不得伪装为用户已拥有的实际设备。

知识条目只提供来源、适用范围和保守检查方向；页面不得把它显示为确定维修结论。

## 6. 验收案例

| 编号 | 输入摘要 | 预期类别 | 预期优先级 | 预期知识匹配与人工处理 |
|---|---|---|---|---|
| R01 | 传动侧异响、振动；未停机；无安全风险 | `MECHANICAL` | `NORMAL` | 无精确知识匹配；人工确认 |
| R02 | 温度升高、冷却风扇不转；已停机；安全风险未知 | `THERMAL_COOLING` | `URGENT` | 无精确知识匹配；记录停机和安全未知 |
| R03 | 传感器数值正常但控制器无法接收数据；未停机；无安全风险 | `SENSOR_COMMUNICATION` | `NORMAL` | 无精确知识匹配；人工确认 |
| R04 | 控制面板无显示且无法启动；未停机；无安全风险 | `ELECTRICAL_CONTROL` | `NORMAL` | 无精确知识匹配；人工确认 |
| R05 | 报警后停机；报警内容、现象与安全风险均未知 | `OTHER_UNKNOWN` | `URGENT` | 无知识匹配；给出报警码、故障现象和安全风险补问 |

说明：R01、R03、R04 即使安全状态已知，由于当前知识库无适用的精确条目，也必须按本版本返回人工确认；但优先级仍由安全风险、停机状态和关键信息缺失情况决定。这避免将“需要人工确认”误当作“紧急”。

## 7. 版本与变更

- 规则版本：`rules-v0.1`
- 知识库版本：初版 5 条有来源条目
- 新增真实设备条目前，必须补充适用机型、来源名称、来源页/章节与来源链接；缺任一项不得参与自动匹配。
