# 分层设备匹配约定

## 两层匹配键

知识条目新增 `equipment_category`（设备大类）和 `subsystem`（子系统）。平台分两层检索：

```text
第一层参考：equipment_category + subsystem
第二层确认：brand + equipment_model + controller_system + software_version + alarm_code
```

企业设备先在设备台账中用 `asset_token` 登记，再将该标识映射到上述字段。工单优先读取 `asset_token` 对应的台账信息；只有缺少台账映射时，才使用工单填写的信息。

## 匹配规则

1. 第一层仅按设备大类和子系统召回“参考候选”。它用于归类、补问和通用安全提醒，不能输出某个型号的报警含义、维修步骤或确定结论。
2. 第二层中，品牌、设备型号和控制系统必须完全一致，才可输出某条原厂知识的具体处置方向。
3. 知识条目的 `software_version=ANY` 表示该条原厂资料未限定控制器具体版本；其他值必须与设备版本一致。
4. 工单有报警代码时，第二层优先匹配相同报警代码；知识条目没有报警代码时，仅在设备键完全一致且核心现象一致时进入人工复核候选。
5. 仅第一层命中、任一第二层关键设备键缺失、品牌/型号/控制系统不同、报警码不一致，或存在多个同等候选时，均不返回确定知识，改为“参考候选 + 人工确认”。

## 当前设备大类和子系统

| 设备大类 | 已覆盖子系统 |
|---|---|
| `CNC_MACHINING` | `THERMAL_COOLING`、`COOLANT_SYSTEM`、`PNEUMATIC`、`LUBRICATION` |
| `CNC_CONTROL` | `COOLANT_SYSTEM`、`LUBRICATION` |
| `VARIABLE_FREQUENCY_DRIVE` | `DRIVE_MOTOR`、`DRIVE_ELECTRICAL`、`DRIVE_SAFETY` |

## 公开目录与企业接入边界

公开设备目录只提供标准化品牌、型号、控制系统和原厂资料来源。企业接入时必须完成本单位设备台账映射；平台不能仅凭工单文本猜测未知设备型号。
