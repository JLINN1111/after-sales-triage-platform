# 真实工单标注与影子运行约定

## 导入前置条件

真实工单只能在已获业务授权的受控环境中脱敏。导入文件不含客户名称、联系人、电话、邮箱、地址、精确地理位置、原始设备序列号或原始工单编号；只使用 `source_ticket_token`、`asset_token` 和 `case_family_token` 等脱敏标识。

运行 `python 运行脚本/validate_deidentified_tickets.py --input <本地脱敏CSV> --report <本地报告JSON>` 后，所有机械扫描发现项都必须修正；随后仍须由人工复核无法由规则可靠识别的姓名、地址或上下文敏感信息。

## 双人标注

1. 两名具有售后或维修业务知识的标注人独立填写 `双人标注导入模板.csv`。
2. 类别、是否必须人工确认和案例家族必须一致；不一致记录进入分歧复核，不得直接进入训练集。
3. 同一真实事件的多种描述共享同一个 `case_family_token`，永不跨训练、验证或最终测试集合。
4. 训练集只接收完成复核的脱敏工单；安全、停机、状态未知和信息不完整样本仍必须保留人工确认标记。

## 独立测试与影子运行

- 新版本训练前，由未参与标注和调参的人员按时间、设备型号或站点隔离保管新的测试集；已使用的课程冻结测试集不得复用为下一版本最终测试。
- 影子运行只展示规则、知识和模型建议，不改变工单状态、不自动派工、不输出维修结论。
- 使用 `影子运行评估模板.csv` 记录人工最终结论、是否一致和误差类型。重点监测高风险漏拦截、错误自动建议、未知设备和新故障表达。
- 在真实数据上完成独立验收前，平台仍只能称为分诊辅助原型。
