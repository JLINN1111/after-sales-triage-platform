## 你需要完成的功能

1. 新建知识匹配服务，读取知识库和设备台账。
2. 第一层按 `equipment_category + subsystem` 召回参考候选，结果标记为 `REFERENCE`，必须建议人工确认。
3. 第二层按品牌、型号、控制器、版本范围和报警码确认；只有完全符合时标记为 `EXACT`，并返回原厂知识编号与处置方向。
4. 无候选时标记为 `NONE`，提示补充品牌、型号、控制器、版本和报警码。
5. 工单提交后自动保存 `knowledge_ids`、`reference_knowledge_ids`、`knowledge_match_level`、人工确认原因和补问内容；工单详情页清楚展示三种结果。
6. 安全风险、已停机、设备信息缺失或仅参考命中时，不得输出确定维修结论。
7. 将用户端设备类型改为通俗选项：数控机床/加工设备、注塑机、输送线/传送带、空压机、电机控制箱/变频器、其他设备/不清楚；设备型号改为可选，并提示用户查看铭牌、不清楚可留空。
8. 用户端不得展示设备大类、子系统、PLC、IGBT 等技术字段；系统在后台映射设备大类并推断子系统。
9. 前台类型映射按字段定义执行：`CNC→CNC_MACHINING`、`INJECTION→INJECTION_MOLDING`、`CONVEYOR→CONVEYOR`、`AIR_COMPRESSOR→AIR_COMPRESSOR`、`VFD→VARIABLE_FREQUENCY_DRIVE`；`OTHER` 不自动映射。数控工单仅在描述出现控制屏、程序、通信、控制器或报警画面等线索时，额外召回 `CNC_CONTROL` 参考候选。

## 对接接口

成员1已建立 `app/services/triage_service.py`。你的知识匹配服务需提供一个可调用函数：

```text
knowledge_matcher(ticket, rules_result) -> {
  knowledge_ids, reference_knowledge_ids, knowledge_match_level
}
```

`knowledge_match_level` 必须返回 `EXACT`、`REFERENCE` 或 `NONE`。统一分诊入口会在规则分诊后调用该函数；`REFERENCE` 与 `NONE` 会自动追加人工确认原因。
