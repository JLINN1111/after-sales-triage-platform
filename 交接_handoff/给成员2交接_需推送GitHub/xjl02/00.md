# 阶段二成果确认（我已完成）

## 我已完成的功能

1. 新建 `app/services/knowledge_matcher.py`，提供 `match_knowledge(ticket, rules_result)`，返回 `knowledge_ids`、`reference_knowledge_ids`、`knowledge_match_level`。
2. 实现三层匹配：
   - `EXACT`：设备台账编号、报警码及品牌/型号/控制系统/版本可确认时返回，可展示原厂处置方向；
   - `REFERENCE`：仅设备大类/子系统一致或关键信息不全时返回，建议人工确认；
   - `NONE`：无候选时返回，提示补充设备信息。
3. 安全风险 `YES` 或已停机 `YES` 时，即使设备键完全匹配也降为 `REFERENCE`，不输出确定维修结论。
4. 前台设备类型按约定映射：`CNC`、`INJECTION`、`CONVEYOR`、`AIR_COMPRESSOR`、`VFD` 分别映射，`OTHER` 不自动映射；数控工单出现控制屏、程序、通信、控制器或报警画面等线索时，额外召回 `CNC_CONTROL` 参考候选。
5. 接入统一分诊入口：工单提交路由改为调用 `triage_ticket(ticket, match_knowledge)`，将匹配结果写回工单字段；未出现 `knowledge_pending` 误报为无匹配的情况。
6. 工单详情页按 `数据资料/展示词映射.md` 显示中文类别、优先级、知识匹配等级和人工确认原因，不再直接展示英文内部代码。
7. 保留你的 `rules.py`、`missing_info.py`、`triage_service.py` 及返回字段名不变，未改动成员1负责文件。
