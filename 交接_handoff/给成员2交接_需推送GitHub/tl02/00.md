## 使用顺序

1. 先阅读本文件的“必读源文件”和“接口约定”。
2. 实现并单独验证知识匹配服务。
3. 再接入成员1的统一分诊入口、工单提交路由和详情页。
4. 提交代码、自动检验结果和涉及文件清单，供成员1验收。

## 你需要完成的功能

1. 新建 `app/services/knowledge_matcher.py`，提供：

   ```python
   match_knowledge(ticket, rules_result) -> dict
   ```

2. 读取正式知识库和设备台账，按以下规则返回：

   ```text
   knowledge_ids, reference_knowledge_ids, knowledge_match_level
   ```

   - `EXACT`：仅在可从设备台账确认品牌、型号、控制系统、版本范围和报警码适配时返回；可展示对应原厂处置方向。
   - `REFERENCE`：仅设备大类/子系统一致，或设备关键信息不全时返回；只能展示参考信息，必须转人工。
   - `NONE`：没有可用候选时返回；提示补充设备信息或转人工。

3. 前台设备类型映射：`CNC→CNC_MACHINING`、`INJECTION→INJECTION_MOLDING`、`CONVEYOR→CONVEYOR`、`AIR_COMPRESSOR→AIR_COMPRESSOR`、`VFD→VARIABLE_FREQUENCY_DRIVE`；`OTHER` 不自动映射。数控工单出现控制屏、程序、通信、控制器或报警画面等线索时，可额外召回 `CNC_CONTROL` 参考候选。

4. 不得把公开基准设备当作企业实际资产。设备台账无法确认品牌、型号、控制系统或版本时，禁止返回 `EXACT`；只能返回 `REFERENCE` 或 `NONE`。

5. 调用 `app/services/triage_service.py` 的 `triage_ticket(ticket, knowledge_matcher)` 接口接入工单提交路由，将结果写入工单字段。未接入知识匹配前，统一入口会标记 `knowledge_pending=True`，不得把它显示为“无匹配”。

6. 更新工单详情页：使用 `数据资料/展示词映射.md` 显示中文类别、优先级、知识匹配等级和人工确认原因；不得直接向用户展示英文内部代码。

7. 用自动检验覆盖至少四种情形：精确匹配、仅参考匹配、无匹配、安全/停机优先。验证保存字段、人工确认标记和中文页面展示。

## 接口约定

成员1统一分诊入口会在规则分诊后调用：

```python
knowledge_matcher(ticket, rules_result)
```

返回值至少包含：

```python
{
    "knowledge_ids": [],
    "reference_knowledge_ids": [],
    "knowledge_match_level": "EXACT" | "REFERENCE" | "NONE",
}
```

`REFERENCE` 或 `NONE` 会由统一入口自动追加人工确认原因。不要改动成员1的 `rules.py`、`missing_info.py` 或返回字段名称。
